# Minigame Mansion: design (v1)

Working title. Status: awaiting Sander's approval.

## What it is and who it is for

A party game for Sander and 2-4 friends (up to 8 supported), each on their own Windows PC on the same local network. A session is a run of short minigames (30-60 seconds each) with a running scoreboard and a winner's podium at the end. Success for v1: four friends can start the exe, find each other without typing IP addresses, play a full session of four different minigames, and want a rematch.

Constraints from Sander: built entirely by AI agents, no modelling or coding by him, free tools only, shareable as a Windows exe.

## Session flow

1. **Title screen**: Host game / Join game / Quit. Enter a name, pick a colour.
2. **Lobby**: a small mansion hall where joined players can run around. The host picks the number of rounds (default 8) and presses Start. Empty seats can be filled with bots.
3. **Round**: a random minigame (no repeat until all have been played). 3-second title card with a one-line rule, countdown, play, result.
4. **Scoreboard** after each round: placement points (1st 4, 2nd 3, 3rd 2, 4th 1, everyone else 0), shown as a bar race.
5. **Podium** after the last round, then back to the lobby.

## Players

Blob characters: a capsule body with eyes, a player colour and one of a few hats. No skeletal animation; movement life comes from code (squash and stretch, lean, bounce). One shared controller for every minigame:

- Move (WASD / left stick), jump (Space / A), action (left mouse or E / X).
- The default action is a short shove that pushes other players. A minigame may replace the action or disable jump.
- Third-person camera fixed per minigame (arena view), so there is no camera control to learn.

## Minigames in v1

All four use the shared controller, so they are cheap to build and immediately familiar.

| Minigame | Rule | Ends when |
|---|---|---|
| Floor Is Lava | Hex platforms sink a few seconds after being stepped on; shoving allowed | One player left, or 60 s |
| Bumper Sumo | Round platform that shrinks; shove others off | One player left, or 60 s |
| Hot Potato | One player holds a bomb with a hidden fuse; touching passes it; holder is out when it blows; repeats | One player left |
| Coin Scramble | Coins rain into an arena with moving obstacles; a shove makes the victim drop coins | 45 s, most coins wins |

More minigames are added after v1, one at a time.

## Architecture

- **Godot 4.7, GDScript, high-level multiplayer (ENet).** One player hosts; the host is the authority for all game state (positions are simulated per owner and validated loosely, since this is a friends-only LAN game with near-zero latency). Default port 24565.
- **LAN discovery**: the host broadcasts on UDP so the Join screen lists available games. Manual IP entry stays as a fallback.
- **Units**
  - `Net`: hosting, joining, discovery, player roster (name, colour, hat, bot flag).
  - `Session`: round order, scores, flow between lobby, round, scoreboard and podium. Host-driven; clients follow.
  - `Player`: the shared blob controller, synchronised over the network, plus a bot brain that feeds it the same inputs a human would.
  - `Minigame` base class: every minigame is one scene plus one script that implements `setup(players)`, `start()`, and emits `finished(ranking)`. It knows nothing about lobbies or scores, so each one can be built and tested alone by a separate agent.
  - `UI`: title, lobby, title card, scoreboard, podium.
- **Art**: every model is generated by a Blender script in `art/scripts/` using the existing `artlib.py`; flat colours, one shared palette.
- **Audio**: a handful of sound effects generated in code or taken from CC0 packs. No music in v1.

## Error handling

- Host leaves: clients return to the title screen with a message.
- Client leaves mid-round: their blob is removed and the round continues; if one player remains, the round ends.
- Join fails or times out: message on the Join screen, no hang.
- Late joiners wait in spectate until the next round.

## Testing

- `godot-check` and `godot-screenshot` on every change (existing repo rule).
- Each minigame has a bot-only run mode: four bots play it headless to the end, and the run fails if it does not finish with a valid ranking.
- A multiplayer smoke test starts one host and two clients on this PC, plays one full round with bots as input, and checks that all three agree on the ranking.
- Game feel is tuned from Sander's playtest notes; agents cannot judge it.

## Not in v1

Internet play, a board-game layer between rounds, music, unlocks or saved progress, team modes, controller rebinding, non-Windows builds.
